# 六足机器人移动目标跟随与自主避障分层系统

## 技术方案 V6（实验总指导大纲 / PCR-Net++ 主线）

**版本**：V6.0  
**日期**：2026-01-27  
**定位**：在既有“命令空间 MoE + Command Post-Processor（V5 主线）”基础上，补齐一份可直接驱动后续所有工作的【实验设计总指导】；方法主线升级为 **PCR-Net++（y + w + β，且 β 联动后处理）**。  

> 说明：本 V6 不是“工程实现细节手册”，而是把后续训练/评测/消融要怎么做、为什么这样做、成功/失败怎么判定，先钉成统一口径。  
> 任何实现改动必须服从：吞吐优先（3090，2048/4096 并行）、可复现、场景契约可验收、部署一致性（同一 Post-Processor 链路）。

# 0. 总目标与不可动摇约束（Goal & Non-negotiables）

## 0.1 目标能力（论文要证明的东西）

- 在“移动目标跟随（Follow）”与“复杂避障（Avoid）”冲突场景下，出现**稳定、可控、丝滑**的行为选择：减速/让行/绕行/通过门洞等。
- 在复杂多变避障环境 + 地形变化下具备泛化能力，并满足结构化 OOD（S6 hold-out）评测协议。
- 形成可写 RA-L 级证据链：强对照 + 严格消融 + OOD/鲁棒矩阵 + 可解释控制量可视化。

## 0.2 工程/训练边界（必须遵守）

- 单卡 3090，目标支撑 2048/4096 并行；不做无证据的昂贵仿真要素。
- 分层边界：
  - **底层 locomotion 冻结**；底层不使用深度相机（仅 proprio + 特权地形输入，按既有方案口径）。
  - 高层：Teacher 用特权/GT affordance；Student 用相机/深度（仅 Student 分支启用）。
- 控制链路：Follow/Avoid experts 输出 `cmd_vel` → 仲裁/融合 → **Command Post-Processor（限幅/滤波/风险钳制）** → 下发到底层。
- 场景契约：
  - 轴向契约唯一：world +Y 前进；tile 行(i)=+Y；heightfield[a,b]：a=+Y、b=+X；轴映射只允许在 `Terrain.add_terrain_to_map()` 一处。
  - S6 为结构化 OOD hold-out：训练中不出现，作为回归与论文核心证据之一。

## 0.3 本 V6 要“钉死”的论文主张（建议写在摘要/贡献点里）

- P1（y-only 痛点是系统性问题）：在 Follow/Avoid 冲突片段（门洞、贴边绕行、柱阵死胡同）中，y-only MoE 主要失败表现为：
  - 滞后切换：进入高风险区域后才偏向 Avoid，导致 near-miss/碰撞；
  - 风险边界抖动：y 来回切换导致 cmd 抖动、速度振荡与重复 reset。
- P2（β 的核心贡献）：引入风险预算 **β** 并联动 Command Post-Processor 的“约束族参数”，把安全/平滑从“奖励调参问题”转为“机制可控问题”，从而：
  - 显著降低 near-miss、switch rate 与 cmd jerk；
  - 形成可复现实验的 **风险-效率 Pareto 曲线（扫 β）**。
- P3（w 的核心贡献）：引入 **w（命令条件化预测冲突 prior）**，把“提前性”从瞬时门控中解耦出来，进一步降低滞后与切换震荡（尤其在目标动态/感知有噪声时）。

## 0.4 成功判据（不允许只看 success）

> 训练“能跑通”不是成功；必须满足下面的可量化判据，才算达到了 V6 的实验目标。

- 必报曲线与指标：
  - IID（S1/S2）：success、time-to-goal（或 progress/time）、collision、near-miss、cmd jerk、switch rate
  - OOD（S6）：同上 + 视觉退化曲线（Student）+ 动力学随机化曲线
  - **β sweep**：固定策略扫 β，输出 risk vs efficiency 的 Pareto（至少 5 个取点）
- 最小“赢”定义（用于快速决策是否继续投算力）：
  - y+β(link) 相比 y-only：near-miss 与 switch rate 明显下降，且效率（time/progress）不塌缩为“停住刷分”；
  - y+w+β(link) 相比 y+β(link)：在动态/噪声设定下滞后与震荡进一步下降（可通过事件对齐图与 switch rate 体现）。

# 1. 统一语义与接口契约（P0）

> 任何论文结论与工程调试都依赖“语义唯一”。本节是 P0：不统一，后续一切无效。

## 1.1 y 的语义（全链路唯一）

- 采用唯一公式并写入所有文档/代码/日志解释：
  - `cmd = y * cmd_F + (1 - y) * cmd_A`
  - **y = 1 表示 Follow 主导；y = 0 表示 Avoid 主导**

## 1.2 β 的语义（全链路唯一）

- **β 大 = 更保守 / 更安全（更强约束）**
- β 必须与 Post-Processor 参数映射方向一致（见第 4 章）。

## 1.3 终止/奖励阈值一致性

- goal 达成阈值统一口径：**0.1**（环境终止、奖励阈值、重采样策略必须一致）。

## 1.4 Teacher/Student 观测边界

- Teacher：不得创建/刷新深度 buffer（避免吞吐与一致性问题）。
- Student：才启用相机/深度与 Depth→Affordance（或相关感知）链路。

## 1.5 语义与阈值验收 checklist（跑实验前必须通过）

- y 方向验收：
  - 打印/可视化：在“无障碍直走跟随”片段里，y 应趋向 1（Follow 主导），并对应更快进度；
  - 在“障碍逼近/门洞/贴边绕行”片段里，y 应向 0 偏移（Avoid 主导），并对应更低 near-miss。
- β 方向验收：
  - β 增大时：Post-Processor 的约束应变强（safe_dist 增大、max_cmd 变保守、max_delta 更小等）；
  - β sweep 中：风险指标（near-miss/碰撞）随 β 增大应非恶化（允许轻微非单调，但要可解释且总体下降趋势清晰）。
- goal threshold=0.1 验收：
  - 终止、奖励与重采样（如启用）必须用同一个阈值，避免“奖励认为到了、环境不终止”导致统计偏差。
- Teacher/Student 观测验收：
  - Teacher 跑 headless/无相机时不应分配/刷新深度 buffer；
  - Student 才能启用深度，并在退化设定下输出退化曲线。

## 1.6 日志与可视化规范（最小集合）

> 目的：保证每次训练都能回答“为什么好/为什么坏”，避免只剩 reward 曲线。

- 必须记录（每 iteration 或固定频率）：
  - y、w、β 的均值/方差/饱和比例（接近 0/1 的比例）
  - switch rate（见 8.3 的定义口径）
  - cmd jerk（线速度/角速度）
  - near-miss（低 clearance 积分 或 最小间隙统计）
- 必须保存（用于论文图）：
  - 典型 episode 的 y/w/β 时间序列 + 关键事件标注（门洞进入/通过、绕行开始/结束）
  - β sweep 的 Pareto 曲线（同一策略不同 β）

# 2. 方法主线（PCR-Net++：y + w + β，β 联动后处理）

## 2.1 为什么不是“自由残差 Δ”（主线不选 PCR-Net）

- 自由 Δ 容易在仿真刷分但引入新漏洞（高频补偿、抵消后处理、分布外怪异动作）。
- 主线优先选择**有界、语义可解释、可监控**的控制量：y / w / β。

## 2.2 y-only 的典型失败模式（必须在实验中被量化）

- 滞后（late switch）：
  - 进入门洞/贴边/柱阵夹缝后才偏向 Avoid；
  - 表现：near-miss 峰值大、碰撞上升、通过时间抖动大。
- 震荡（chattering）：
  - 风险边界附近 y 来回切换；
  - 表现：switch rate 高、cmd jerk 高、速度出现“进-退-进”。

## 2.2 渐进落地顺序（最稳、最高 ROI）

1) y-only MoE（基线）  
2) y + β（β 联动 Post-Processor）——优先实现并争取拿到主要增益  
3) y + w + β（w 为“命令条件化预测冲突 prior”）  
4) 可选：受限 Δ（仅在遇到明确瓶颈时；必须有界且不破坏后处理安全机制）

## 2.3 PCR-Net++ 的最小形式（论文写法建议）

- 输出：
  - y：仲裁权重（Follow vs Avoid）
  - w：预测 prior（提前性偏置）
  - β：风险预算（联动后处理约束强度）
- 融合（建议固定一种可解释形式，保持单调/有界）：
  - 约定：`y/y_eff` 为 **Follow 权重**；`w` 为 **冲突强度**（`w↑ => 更应偏 Avoid`），因此融入 Follow 权重时取反：
  - `y_eff = clamp((1 - lambda_w) * y + lambda_w * (1 - w), 0, 1)`
  - 其中 `lambda_w` 可固定常数或由简单规则/小网络输出（若输出，需纳入消融）。
- 命令融合与后处理（保持 V5 主线不变）：
  - `cmd_raw = y_eff * cmd_F + (1 - y_eff) * cmd_A`
  - `cmd = PostProcessor(cmd_raw, beta=β, risk=...)`

## 2.4 渐进落地的“停表条件”（节省算力）

- 若 y+β(link) 相比 y-only：
  - near-miss/switch rate 没下降：优先检查 β→参数映射是否生效、near-miss 统计是否正确、冲突片段是否足够出现；
  - 效率崩溃为“停住”：优先收紧映射范围/加进度保底机制，而不是堆 reward 项。
- 若加入 w 后：
  - 只提升 success 不改善 jitter/near-miss：大概率 w 退化为 clearance 分类器 → 回到 3 章重做命令条件化输入/辅助目标。

# 3. w：命令条件化的预测冲突 prior（避免退化）

## 3.1 w 的定义（论文要能一句话说清）

- w 表达“短未来内 Follow 候选命令 vs Avoid 候选命令”的**可行性差异/冲突趋势**，用于提前性仲裁（降低滞后与切换震荡）。

## 3.2 必须命令条件化（否则 w 无意义）

- w 的输入必须包含至少一种“命令条件”信息：
  - 候选命令特征（`cmd_F/cmd_A` 或其投影特征），或
  - 沿候选命令方向的风险估计差值（例如 RiskAlong_F - RiskAlong_A），或
  - 与候选命令相关的短历史一致性特征
- 若 w 与 clearance/距离高度同相关且不提升 jitter/near-miss 指标，则视为退化：回退重做输入与目标定义。

## 3.3 w 的输入最小集合（建议）

> w 的“新意”靠命令条件化站住脚；没有这部分，审稿人会认为只是又加了个门控头。

- 必选（至少一类）：
  - 候选命令本身：`cmd_F`、`cmd_A`（或其投影特征：目标方向投影、横向分量等）
  - 候选命令风险投影：`RiskAlong(cmd_F)`、`RiskAlong(cmd_A)` 或差值
- 建议增加：
  - 短历史（affordance stack / recent cmd / recent risk）用于提前性与去噪
  - 目标运动信息（目标速度/横移趋势）用于动态目标冲突

## 3.4 w 的训练策略两案（先写进文档，后续按实际选）

- A（纯 RL）：w 作为策略输出，由回报驱动；需配合：
  - switch/jitter 正则（限制 y_eff 的高频变化）
  - 事件对齐评测（是否提前进入保守模式）
- B（RL + 辅助头）：增加一个辅助目标稳定 w 的语义，例如：
  - 预测未来 K 步的风险差：`E[Risk_F] - E[Risk_A]`
  - 或预测“哪个候选命令更可行”的二分类（以未来轨迹/风险判定生成伪标签）

## 3.5 w 退化检测（必须做）

- 相关性退化：corr(w, clearance) 过高且对 near-miss/jitter 无改善 → 判退化
- 迟滞退化：w 只有在极近距离才变化 → 仍是滞后式，不满足“预测 prior”定位

# 4. β 联动 Command Post-Processor（丝滑与可控的关键）

## 4.1 机制化目标

- 把“安全与平滑”从纯奖励权衡问题，转为**可解释旋钮 β 调节约束族参数**的问题。
- 强调“部署一致性”：训练与部署共用同一 Post-Processor 机制，仅参数可连续调节。

## 4.2 约束族参数（建议最小集合）

- 至少包含：
  - `safe_dist`（安全间距/风险钳制阈值）
  - `max_cmd`（线速度/角速度限幅）
  - `max_delta`（slew rate / 变化率限制）
  - 风险钳制强度（risk clamp gain 等）

## 4.2.1 参数映射模板（推荐统一写法）

> 原则：单调、有界、可解释；保证 β sweep 时行为可控。

- 统一使用（线性或分段线性）插值：
  - `theta(beta) = theta_min + (theta_max - theta_min) * clamp(beta, 0, 1)`
- 其中：
  - `theta_min`：激进/效率优先端（β=0）
  - `theta_max`：保守/安全优先端（β=1）

## 4.2.2 建议的映射方向（必须与 β 语义一致）

- `safe_dist(beta)`：随 β **增大而增大**
- `max_cmd(beta)`：随 β **增大而减小**（但不能小到无法前进）
- `max_delta(beta)`：随 β **增大而减小**（更平滑）
- `risk_clamp_gain(beta)`：随 β **增大而增大**（更强钳制）

## 4.3 退化防护（β 拉满=停住 的机制约束）

- β=1 不能等价于“几乎无法前进”；必要时限制参数映射范围。
- 必须有进展保底机制（time penalty / progress reward / 低速长期惩罚 或等价约束）。

## 4.3.1 “停住刷分”处理优先级（出现就按这个顺序）

1) 先收紧映射范围：提高 `max_cmd(beta=1)` 的下限，避免 β=1 变成“近似 0 速度”  
2) 再强化进度保底：增加 time penalty 或最小进度软约束（避免长期 v≈0）  
3) 最后才调整其他 reward 权重（避免 reward 体系碎片化）

## 4.4 论文展示方式（必须是曲线，不是单点）

- 固定策略扫 β，报告**风险-效率 Pareto 曲线**（碰撞/near-miss vs 到达时间/进度），并对比 y-only 与 β 不联动的版本。

## 4.4.1 β sweep 评测协议（最小可复现版本）

- 取点：β ∈ {0.0, 0.25, 0.5, 0.75, 1.0}（最少 5 点）
- 固定：相同模型权重、相同 seeds、相同 episode 数、相同任务分布
- 输出：每个 β 点的均值/方差（或 CI），并画 Pareto（risk vs efficiency）

# 5. 场景与任务设计（S1–S6 + 技能定义）

## 5.1 主场景（先打穿，再扩展）

- S1：corridor + gate（门洞走廊）
  - spawn/门洞/goal 段内随机；三段互斥；避免 reset-loop。
- S2：forest（柱阵/障碍林）
  - 稀疏→密集；分布与随机化可控；强调绕行与局部死胡同处理。

## 5.1.1 S1 分布参数（与配置保持一致，便于复现与写论文）

> 以 `hex_scenes_config.py` 为准，easy/hard 插值由 difficulty 决定（d∈[0,1]）。

- 走廊与门洞几何（示例字段）：
  - corridor_width（走廊净宽）
  - gate_width（门洞净宽）
  - gate_count（门洞数量）
  - gate_length + gate_length_jitter（门洞长度与抖动）
  - gate_spacing_min（门洞最小间距）
  - gate_margin_y（门洞距走廊端点的 margin）
  - wall_thickness_m / wall_height_m
- 出生/目标段（用于避免 reset-loop 的关键）：
  - corridor_spawn_buffer / corridor_spawn_span（spawn 段范围）
  - corridor_goal_min_offset / corridor_goal_buffer / corridor_goal_margin（goal 段范围）
- 冲突片段定义（用于统计与可视化）：
  - Gate-approach：进入门洞前 X 秒/米范围
  - Gate-pass：穿越门洞区间
  - Recovery：穿越后恢复速度段

## 5.1.2 S2 分布参数（与配置保持一致）

- 障碍物分布（示例字段）：
  - count_min/count_max（数量）
  - pole_radius_min/max、pole_height_min/max
  - block_ratio、block_size_min/max、block_height_min/max
  - min_dist（最小间距，决定难度与局部死胡同概率）
  - spawn_clear / goal_clear
- 冲突片段定义：
  - Narrow-gap：需要贴边通过的窄缝
  - Detour：必须绕行（局部不可通行导致的路径偏离）
  - Dead-end：短时间内进度为负或接近 0 的段（评估是否能恢复）

## 5.2 扩展场景（训练多样性 + 消融稳定性）

- S3–S5：结构变化/密度变化/组合变化（用于泛化与训练稳定性证据）。

## 5.3 结构化 OOD（核心证据）

- S6：训练绝不出现；作为论文主证据与回归测试基准。

## 5.3.1 S6 hold-out 协议（建议写死）

- 训练中不出现的结构（例）：
  - 特定布局拓扑（如“门洞组合模式/交叉结构”）
  - 特定密度区间（如“极端密集/极端稀疏”）
  - 特定障碍尺寸组合（如“尺寸分布 shift”）
- 评测必须固定：layout seeds、episode 数、difficulty 取点（或固定 difficulty）

## 5.4 技能定义（Follow / Avoid）

- Follow：效率优先（更快到目标、更少绕行），但仍需遵守可行与安全边界。
- Avoid：风险优先（更大间隙、更保守的命令变化），允许效率下降但不能“停住刷分”。

# 6. 奖励函数与行为管理（统一骨架，禁止每场景一套）

## 6.1 高层奖励骨架（建议）

- 任务进展/到达（progress / goal）
- 安全（碰撞、near-miss proxy、风险积分）
- 平滑（cmd jerk、|Δy_eff|、|Δβ|）
- 效率（时间惩罚/能耗 proxy）

## 6.1.1 每项奖励/正则的“漏洞边界”提示（写论文也用得上）

- progress/goal：可能诱导“贴边刮墙”抢进度 → 必须由安全项与后处理兜底
- collision/near-miss：可能诱导“停住” → 必须有进度保底
- jerk/Δy/Δβ：过强会导致“反应迟钝” → 需要通过 w 的提前性弥补，而不是一味加大惩罚

## 6.2 场景差异处理原则

- 默认不做“每场景单独奖励函数”；仅允许同一骨架下的权重/阈值参数化，并进入消融矩阵。

## 6.3 行为管理原则

- 后处理负责强约束（可行、安全、平滑）；网络只输出可解释控制量（y,w,β），降低奖励黑客与仿真漏洞依赖。

# 7. 训练设计（Teacher→Student，全链路可复现）

## 7.1 Stage A：专家预训练（Follow/Avoid）

- 每个专家内引入风格条件（至少 β），得到“专家内可调风格族”。
- 底层冻结；训练预算与并行数固定可复现。

## 7.1.1 专家内风格条件（β）的最小要求

- 目标：同一 expert 在不同 β 下能形成连续的风格变化（更保守 vs 更激进），而不是“换了 β 没反应”。
- 验收：固定场景与 seeds，扫 β 后得到单调趋势（至少 risk 指标随 β 上升下降，效率随 β 上升上升或下降）。

## 7.2 Stage B：仲裁/融合训练（PCR-Net++）

- 冻结专家，训练输出 y,w,β；β 联动 Post-Processor。
- 稳定后可选小步联合微调（需要严格监控漂移与退化）。

## 7.2.1 落地顺序（训练层面）

1) y-only（moe gate）作为基线，先跑出清晰的失败模式曲线  
2) β-only（输出 β，y 仍由 gate 或固定策略给出）验证“联动后处理”的收益  
3) y+β(link)（y 可学，β 可学）  
4) y+w+β(link)（加入 w；若 w 不命令条件化则禁止进入主线）

## 7.3 Stage C：Student 蒸馏（视觉）

- 固定 Teacher；Student 用相机/深度输入蒸馏：
  - 行为对齐：cmd_vel
  - 关键中间量：至少 β（可选 y,w）
- 传感退化训练：noise/blur/dropout 等；报告退化曲线。

## 7.3.1 蒸馏目标（最小集）

- 行为：`cmd_vel`（必须）
- 风格：`β`（强烈建议；否则 Student 难以复现 Teacher 的风险-效率曲线）
- 可选：y 与 w（若用于论文可解释性与事件对齐图）

## 7.4 课程与随机化（建议轴）

- 场景课程：S1 简单→复杂；S2 稀疏→密集；再引入 S3–S5 多样性。
- 随机化矩阵：动力学（摩擦/质量/外扰）+ 视觉退化（student）+ 结构化 OOD（S6）。

## 7.5 复现协议（建议写死）

- 固定：训练 seeds、评测 seeds、评测 episode 数、difficulty 取点
- 固定：每个对照/消融的训练预算（总步数/迭代数一致）
- 建议：统一日志频率与指标计算口径（见 1.6 与 8 章）

# 8. 评测协议与指标（RA-L 证据链）

## 8.1 IID（S1/S2）

- 固定 seeds、固定 episode 数、统一训练预算；报告均值/方差或置信区间。

## 8.2 OOD 与鲁棒性矩阵

- S6 hold-out（结构化 OOD）
- 视觉退化（student）：noise/blur/dropout
- 动力学随机化：摩擦/质量/外扰

## 8.3 必报指标（建议最小集合）

- 任务：成功率、到达时间/进度
- 安全：碰撞率、near-miss（低 clearance 积分/最小间隙统计）
- 丝滑：cmd jerk、switch rate（y_eff 变化事件）、Δβ 统计
- 可控：扫 β 的风险-效率 Pareto（同一策略、多点曲线）

## 8.3.1 指标口径（建议写死，避免“各算各的”）

- near-miss（推荐主指标）：低间隙积分
  - 例：`near_miss = sum_t max(0, c_thr - clearance_t) * dt`
  - 其中 `c_thr` 固定阈值（与机器人 clearance/场景尺度相关），清晰报告取值
- switch rate（y_eff 抖动）：单位时间内 y_eff 的“显著变化事件”计数
  - 例：当 `|y_eff(t) - y_eff(t-1)| > dy_thr` 计一次事件
  - dy_thr 固定（例如 0.2），并报告每秒或每 episode 平均
- cmd jerk：命令一阶差分的 RMS 或 L1（线速度与角速度分别统计）
- risk vs efficiency（Pareto）：
  - risk：collision 或 near-miss（建议 near-miss 为主）
  - efficiency：time-to-goal 或 progress/time（需要在文档中固定选择一种）

## 8.4 可解释性展示（图的要求）

- y、w、β 时序曲线与关键事件对齐（门洞、绕行、贴边、目标横移等），展示提前性与平滑切换。

## 8.5 评测矩阵（最小集合）

- IID：S1、S2（difficulty 取固定点或固定分布，写死）
- OOD：S6（hold-out）
- Student 视觉退化：noise/blur/dropout（写明强度取点）
- 动力学随机化：摩擦/质量/外扰（写明范围取点）

# 10. 风险清单与失败判据（快速迭代）

## 10.1 语义风险（致命）

- y/β 方向不一致、公式不一致：直接判失败，先统一再跑实验。

## 10.2 w 退化风险

- w 仅学 clearance：不提升 jitter/near-miss/switch rate → 回退重做命令条件化输入与目标定义。

## 10.3 β 退化风险

- β 拉满=停住刷分：收紧 β→参数映射范围 + 强化 progress 机制；重新评估 Pareto 单调性。

## 10.4 Teacher/Student 混淆风险

- Teacher 仍分配/刷新深度 buffer：吞吐与一致性受损，必须先修复再做大规模训练。

## 10.5 出现问题时的优先排查顺序（建议写死）

- “结果反了/解释不通”：
  1) y/β 语义方向与公式是否一致（1.1/1.2）
  2) goal threshold 是否一致（1.3）
  3) 指标口径是否一致（8.3.1）
- “β sweep 没有 Pareto/行为不随 β 变”：
  1) β→Post-Processor 映射是否真的生效（4.2.1/4.2.2）
  2) 是否被别的限幅/规则覆盖导致 β 无效
- “β 拉满停住”：
  1) 提高 max_cmd 下限、收窄映射范围（4.3.1）
  2) 增强进度保底（time/progress）
- “w 没用/变成 clearance classifier”：
  1) 输入是否命令条件化（3.3）
  2) 是否需要辅助目标稳定语义（3.4）
