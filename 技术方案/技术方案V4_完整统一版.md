# 1. 项目概述：这个系统到底要干什么

## 1.1 背景：为什么是六足、为什么是“移动目标跟随 + 自主避障”

现有视觉运动控制工作多聚焦于“地形适应 locomotion”（在崎岖地形不摔倒），而六足机器人因其冗余支撑具备独特优势：  

- **静态稳定性强**：三足支撑即可保持稳定，具备更大的“稳定性-效率”调节空间  
- **可调节的运动风格更丰富**：同样朝向目标，六足可以在速度、摆动、支撑策略上更大幅度地进行安全-效率权衡  
- **更适合将“视觉质量”纳入系统指标**：六足并非必须高动态奔跑，完全可以把“相机稳定/视觉可用性”当作可学习目标

本项目的“终极落点”不是训练一个单一策略，而是构建一个可复现、可解释、可扩展的**分层跟随与避障系统**：  

- **底层**专注于“怎么走得稳、怎么走得顺”（关节级控制）  
- **高层**专注于“跟随还是避障、走什么命令”（策略级决策）  
- 中间通过 **Command Post-Processor** 形成低耦合接口，使系统能被工程化迭代与论文化表达

## 1.2 系统最终目标（面向论文与工程）

**最终系统能力**：在复杂地形上实时跟随移动目标，同时保证视觉可用性（相机稳定/深度图质量不崩溃），并能自主选择绕行/跨越等短期最优避障路线。  
**你阶段总结对齐的长远规划（论文目标）**：  

1) Phase 1：HexTerrain 上获得稳定行走控制策略（底层基座）  
2) Phase 2：引入跟随与避障奖励，构建端到端多模态策略（Depth + Target / 或 Depth→Affordance→Policy）  
3) Phase 3：加入相机域随机化与视觉模糊抗性训练  
4) 最终目标：论文展示“复杂地形中实现移动目标跟随与自主避障”的六足系统，单策略可完成行走与跟随（或分层系统达到可部署）

# 2. 问题定义与关键约束（必须读懂）

## 2.1 任务拆分：为什么必须分层

如果将任务定义为端到端 `depth + proprio + target_state -> joint actions`：  

- 输入维度极高（depth 128×128）且噪声大  
- 输出是 18 维关节动作，接触不连续导致策略梯度难稳定  
- “跟随目标”与“稳定行走”在奖励上存在强冲突，且移动目标带来非静态决策，容易出现 credit assignment 崩溃  
- 工程上难调试、难复现、难解释

因此采用分层：  

- **底层**解决：在任意速度指令下稳定执行（tracking + stability）  
- **高层**解决：在感知与目标动态驱动下输出可执行命令（cmd_vel + 门控 y）  
- **接口层**解决：MoE 融合后的命令稳定化（Command Post-Processor）

## 2.2 核心变量：门控权重 y（MoE Arbitration, V5 核心语义）

引入连续变量 `y ∈ [0,1]` 表征 Follow/Avoid 的权衡：

- `y → 1`：Follow 主导（跟随优先）
- `y → 0`：Avoid 主导（安全优先）

**理论深化（用于论文表达）**：`y` 是**显式仲裁变量**，只负责专家权重，不再承担速度油门语义：  

- `cmd = y * cmd_F + (1 - y) * cmd_A`  
- 速度与转向能力由专家命令直接表达，不再由门控隐式缩放  
- 该解耦结构使消融更干净、解释更稳定（避免“y 既是门控又是油门”的混淆）

# 3. 系统总体架构：模块、数据流、频率与边界

## 3.1 整体架构图（概念 + 工程落地一致）

```
(高层 5–10Hz)
Depth (128×128) ─► Affordance Estimator ─►  {Occupancy 16×16, PassableGap 16×16, LowObstacle 16×16, Difficulty d∈[0,1]}
TargetState + RobotState ──────────────────►  Follow Expert ─► cmd_F (vx, vy, ωz)
TargetState + RobotState ──────────────────►  Avoid Expert  ─► cmd_A (vx, vy, ωz)
TargetState + RobotState ──────────────────►  Gate Policy   ─► y ∈ [0,1]
                                                         │
                                                         ▼
(接口层 5–10Hz)                               Command Post-Processor
                                        cmd = y*cmd_F + (1-y)*cmd_A → commands

(底层 50Hz)
Proprio (67) + Privileged VGF (30) + Height Map (187) + commands ─► EGPO Locomotion Policy ─► 18-d actions
```

## 3.2 数据流与频率建议（可工程调整，但逻辑必须保持）

- 底层控制（关节/力矩）：50Hz（与仿真 step 对齐）
- 高层决策：5–10Hz（降低决策噪声与训练不稳定）
- 相机/深度更新：10–30Hz（根据渲染开销与学习需求）
- affordance 估计：10Hz（与相机更新同步或更低）

## 3.3 关键边界（V5 强制）

- **底层 EGPO 不使用深度相机输入**：其地形输入为特权高度图/地形高度采样（height map），只用于 Phase 1 locomotion 学习  
- **深度相机输入只用于高层**：用于 affordance 估计与跟随/避障策略（Teacher/Student）  
- 高层不直接输出关节动作：仅输出 cmd_vel 与门控 y；命令稳定化由 Post-Processor 完成

# 5. 环境与观测体系：多模态观测字典、缓冲区、Reset 语义、坐标系统一

## 5.1 观测字典设计（你当前代码已实现，V5 固化）

环境输出：

```python
obs_dict = {
  'proprioception': obs_buf,      # (N, 67)
  'privileged':     obs_vgf_buf,  # (N, 30)
  'terrain':        obs_terrain_buf, # (N, 187)  ← 特权高度图/高度采样
  'depth':          depth_images, # (N, 1, H, W) ← 只给高层
  'robot_state':    robot_state_buf, # (N, 9)   ← 高层
  'target_state':   target_state_buf, # (N, 2)   ← 高层
}
```

## 5.2 底层 proprioception（67维）——按你代码逐项拆解（强一致性）

你当前 `hex_terrain.py` 中构造 `obs_buf` 的拼接顺序是：

- `base_quat` × `obs_scales.quat`：4维（四元数格式 **[x,y,z,w]**，Isaac Gym 标准）
- `base_ang_vel` × `obs_scales.ang_vel`：3维
- `base_lin_acc` × `obs_scales.lin_acc`：3维
- `(dof_pos - default_dof_pos)` × `obs_scales.dof_pos`：18维
- `dof_vel` × `obs_scales.dof_vel`：18维
- `torques` × `obs_scales.dof_torque`：18维
- `commands` × `commands_scale`：3维（vx, vy, ωz）

合计：4+3+3+18+18+18+3 = **67**

> V5 强制：四元数必须保持 `[x,y,z,w]` 约定，与 yaw 提取、`quat_rotate_inverse()` 一致，否则高层 heading/target 坐标变换会产生系统性错误。

## 5.3 特权 privileged（30维）——用于底层 EGPO（VGF）

你当前 `obs_vgf_buf` 的构造（30维）为：

- `base_lin_vel`：3维
- `projected_gravity`：3维
- `rb_force_norm`：24维（对 `penalised_contact_indices` 与 `feet_indices` 的接触力范数拼接/统计）

合计：3 + 3 + 24 = **30**

> 注意：这类特权信号可显著提升 locomotion 学习效率；部署期可通过 estimator 或其他观测替代（见后文规划）。

## 5.4 特权地形输入 terrain（187维）——高度图/高度采样（V5 关键澄清）

你当前 `obs_terrain_buf` 来自：

```python
height = clip(root_z - 0.025 - measured_heights, -1, 1)
obs_terrain_buf = height * obs_scales.height_measurements
```

其中 `measured_heights` 是围绕机器人采样的地形高度点集合（典型为 11×17 = 187 点）。

**V5 强制澄清**：  

- 这 187 维是底层 EGPO 的“特权高度图观测”（height map / height samples）  
- 它不是深度相机输入  
- 它用于训练底层具备地形适应能力（尤其在复杂地形保持稳定）

## 5.5 高层 robot_state（9维）与 target_state（2维）——用于跟随

你当前 `robot_state_buf` 定义为：

- x 位置（local）：`root_states[:,0] - env_origins[:,0]`
- y 位置（local）：`root_states[:,1] - env_origins[:,1]`
- yaw：由四元数 `[x,y,z,w]` 推导
- vx：`base_lin_vel[:,0]`
- vy：`base_lin_vel[:,1]`
- omega_z：`base_ang_vel[:,2]`
- height：相对地面高度（`root_z - mean(measured_heights)`）
- roll：四元数推导
- pitch：四元数推导

target_state 的基础形式沿用 `goal_buf`：约定为“**机器人坐标系下的相对目标 (x,y)**”，并通过：

- `NavigationTaskManager` 维护 local target
- `_update_goal_buffer()` 完成坐标变换同步

若启用 `heading_offset_rad`（例如将 +Y 作为前向），高层 state yaw 与 target_state 必须在**同一坐标系**内对齐（在高层观测里同步旋转 target_state，而不是修改 env 内 goal_buf 语义）。

> V5 强制：goal_buf 必须采用 **in-place 更新**（你已经实现），避免训练过程中 tensor 重新绑定导致 Runner/图捕获错误。

**朝向/坐标标准（固定为 +Y 前进）**

- `yaw_raw=0` 表示世界 +X 方向（Isaac Gym 默认）。
- 机器人前进方向为机体 +Y。
- `yaw_policy = wrap(yaw_raw + heading_offset_rad)`，**标准取值**：`heading_offset_rad = +0.5*pi`。
- 出生朝向目标：`yaw_spawn = atan2(goal_delta_y, goal_delta_x) - heading_offset_rad + yaw_jitter`。
- 凡是 `goal_local -> goal_world` 的旋转、heading_error 计算，都必须使用同一 `yaw_policy` 口径。

> 目标：使高层规划器训练具有强绑定的地形任务（Gate/Slalom/Gate-on-Slope），同时保持物理可行性（Kinematics-Constrained）。

## 6.1 关键现状与边界（工程入口）

- 地形生成入口在 `legged_gym/utils/terrain.py`（Terrain.__init__ → make_terrain）
- 分支顺序通常为：`if cfg.curriculum: ... elif cfg.selected: ...`
- 必须明确：训练期是否走 curriculum；如果 config 中设置 `selected=True` 但未关闭 curriculum，实际行为可能与预期不一致  
  - **V4 要求**：明确写死训练期逻辑：  
    - Phase 1 locomotion：`curriculum=True, selected=False`（泛化地形）  
    - Phase 2/3 tracking：`curriculum=True`，并引入导航导向地形 primitives

## 6.2 机器人运动学包络（Kinematic Envelope）——用于参数化 Gate/Slalom

V3.2 的核心工程原则：生成导航地形必须以“可通行包络”而非机身宽度拍脑袋。建议统一以下参数（以 URDF/实物为准）：

- `W_body`：机身宽度  
- `L_body`：机身长度  
- `W_env`：运动学/摆腿裕度（含足端摆动横向空间）  
- `D_react`：最低反应距离（用于弯折/绕障的最小前瞻距离）

V4 要求：Gate 宽度、Slalom 间距等必须满足：

- 不出现物理不可通行（训练会崩溃并污染策略）
- 难度参数化要与 curriculum difficulty `d∈[0,1]` 建立明确映射（可复现实验）

## 6.3 新增导航地形图元（Terrain Primitives）（必须落地）

### 6.3.1 Gate（门洞 / 窄缝）

训练目标：强制策略学习“对齐 + 低碰撞”的局部规划。  
工程原则：

- 通过“走廊侧墙抬高”阻止策略绕边走直线
- Gate 宽度随难度收紧，但必须 ≥ `W_body + 2*W_env`

### 6.3.2 Slalom（蛇形绕障）

训练目标：强制策略学习“连续曲线绕障”，与 subgoal 平滑性强绑定。  
工程原则：

- 通过“走廊 + 交替障碍柱”强制蛇形路径
- 纵向间距与横向偏移随难度变化（参数化映射）

参数化示例（V3.2 给出的建议形式，V4 固化为默认实现之一）：

- 纵向间距：`S_long(d) = S_max - (S_max - S_min) * d`
- 横向偏移幅值：`Y_offset(d) = Y_max * (0.3 + 0.7*d)`
  并对下界做约束：由 `L_body` 与 `D_react` 限制避免不可行。

### 6.3.3 Gate-on-Slope（坡上门，复合难例）

# 7. 底层运动（Phase 1）：EGPO + 特权高度图（Height Map）+ Encoder（你的真实实现）

> 本节是 V5 的底层核心：它既是工程基座，也是后续高层训练的“动力学执行器”。

## 7.1 Phase 1 的目标定义（与你阶段总结一致）

- 在 HexTerrain 上获得稳定行走控制策略  
- 强调：在复杂地形仍能稳定运动（不摔倒/不震动过大）  
- 将“相机稳定性/视觉可用性”落实到 reward（即使底层不使用相机，也要学会“走得稳”）

## 7.2 EGPO 算法：你当前实现的训练数据流（按代码实际）

你当前 Runner（`expert_guided_encoder_runner.py`）训练循环的核心数据流是：

1) `obs_dict = env.reset_separate()`  
2) 取三类底层输入：  
   - `obs = obs_dict['proprioception']` (N,67)  
   - `obs_vgf = obs_dict['privileged']` (N,30)  
   - `obs_terrain = obs_dict['terrain']` (N,187)  
3) 早期从环境取专家动作：`expert_actions = env.get_expert_actions()` (N,18)  
4) 编码与拼接：  
   - `obs_splice = cat(obs, obs_vgf)` → (N,97)  
   - `obs_terrain_latent = actor_critic.encode_terrain(obs_terrain)` → (N,143)  
   - 同时维护 obs_hist（num_hist=20）用于 LSTM/historical encoder 训练  
5) 动作生成：  
   - `agent_actions = π(obs_splice, terrain_latent)`  
   - `alpha_t = 1 - min(it/expert_interface_iter, 1)`  
   - `actions_exec = alpha_t * expert_actions + (1-alpha_t) * agent_actions`  
6) 环境步进：`obs_dict, rewards, dones, infos = env.step_separate(actions_exec)`  
7) update：PPO loss + estimator loss + lstm encoder loss + BC loss

## 7.3 EGPOEncoder 的关键损失项（你当前实现已包含，V5 固化其意义）

在 `EGPO_encoder.py` 中，除 PPO 基本项外，包含三个对“可部署性”非常关键的辅助损失：

### 7.3.1 Privileged Estimator Loss（特权估计器）

你当前逻辑等价于：

- 输入：`obs_batch[..., :67]`（proprio）
- 预测：`actor_obs_priv_estimator(proprio)`
- 监督：`obs_batch[..., 67:97]`（privileged 30维）
- 损失：MSE

**意义**：为未来“部署去特权”做准备（即使目前训练仍用真值 privileged）。

### 7.3.2 LSTM Encoder Loss（历史编码器→地形编码）

你当前逻辑等价于：

- teacher：`encode_terrain(obs_terrain)` 产生 `terrain_latent`
- student：`LSTM_encode(obs_hist_padded, masks)` 预测同一个 latent
- 损失：MSE

**意义**：为未来“部署去真值高度图”做准备（利用历史 proprio/交互推断地形特征）。

### 7.3.3 BC Loss（专家行为克隆项）

你当前实现的核心是：  

- 早期对 expert_actions 的 log_prob 施加额外引导项  
- 随 `expert_interface_iter` 逐渐衰减退出专家

**工程经验建议（V5 固化为可调超参）**：  

- `expert_interface_iter` 过短：学不到稳定地形适应  
- 过长：策略过拟合专家，探索不足  
- V5 推荐：以日志监控“camera_stability 收敛速度 + success/跌倒率”为依据动态调整（见执行清单）

## 7.4 EGPO 输入“高度图特权观测”的定位（你最新补充，V5 强制）

- `obs_terrain_buf (187)` 属于**特权高度图观测**（height map / sample）

# 8. 高层感知：Affordance Estimator（Depth→Occupancy/PassableGap/LowObstacle）

## 8.1 Affordance 的定义（V3 创新点固化）

定义：

- `O ∈ [0,1]^(16×16)`：Occupancy（障碍占用概率）
- `G ∈ [0,1]^(16×16)`：PassableGap（可通行间距/通道宽度提示）
- `L ∈ [0,1]^(16×16)`：LowObstacle（低障通道，语义为“底盘可通过”，不是足端踩跨）
- `d ∈ [0,1]`：Difficulty（从 `G` 推导，`d = 1 - mean(G)`）

组合：`A = {O, G, L, d}`  
直觉解释：

- `d≈0`：简单地形 → 建议门控 `y≈1`（Follow 主导）  
- `d≈1`：困难地形 → 建议门控 `y≈0`（Avoid 主导）

## 8.2 你当前网络结构（`affordance_estimator.py`，V3 版本）

- Depth Encoder：ResNet-18 风格修改版  
  - 输入：(B,1,128,128)  
  - 输出：(B,256,8,8)  
- Multi-Head Decoders：  
  - Occupancy Head：输出 16×16  
  - Passable Gap Head：输出 16×16  
  - Low Obstacle Head：输出 16×16  
- Difficulty 不再单独预测，直接由 `G` 推导  
- V3 优化：输入归一化 + 空间注意力聚合局部障碍特征（增强可解释与稳健）

## 8.3 训练数据与标签策略（V4 推荐最小闭环）

**目标**：不依赖人工标注，构建可扩展训练集。  
建议两条路线（可并行）：

### 路线 A：仿真真值监督（最快闭环）

- 利用仿真地图/高度场生成 occupancy/passable_gap/low_obstacle GT  
- low_obstacle 基于高度阈值 `crossable_height_max`（ground 当前设为 0.08），语义为“底盘可通过”  
- passable_gap 基于障碍膨胀与机身宽度（clearance）计算通道宽度  
- difficulty 由 `passable_gap` 推导：`1 - mean(passable_gap)`

### 路线 B：自监督 difficulty（更贴合“实际可通行性”）

- 随机控制（或低层策略）采样轨迹
- 用 IMU/jitter/slip/碰撞等统计构造 difficulty 标签  
- 使 difficulty 更贴近“机器人视角的通过难度”，更利于门控 y 学习

## 8.4 评估指标（感知层）

- occupancy/passable_gap/low_obstacle：IoU / F1 / AUC  
- difficulty：MSE / Rank correlation（越难越大是否保持排序）  
- 下游指标：使用 estimated affordance 的 Student 是否逼近 Teacher

# 9. 高层跟随与避障（Phase 2/3）：Command-Space MoE（Follow/Avoid + Gate）

> 跟随与避障高层策略采用 **命令空间 MoE**：两个专家直接输出 `cmd_vel`，门控 `y` 仅做权重仲裁；Teacher–Student 仅用于 affordance（GT→估计）蒸馏。

## 9.1 高层输出空间（V5 固化）

- **Follow Expert**：`cmd_F = [vx, vy, ω]`
- **Avoid Expert**：`cmd_A = [vx, vy, ω]`
- **Gate**：`y ∈ [0,1]`

融合公式：

`cmd = y * cmd_F + (1 - y) * cmd_A`

> **强制约束**：`y` 只做仲裁，不再作为速度缩放或转向增益。

## 9.2 动作分布与数值稳定性

- `cmd_vel` 建议使用 **Tanh-Squashed Gaussian**（输出后再乘物理尺度）
- `y` 使用 Sigmoid 或 Beta（可选），**禁止 clamp 输出**
- 训练时必须记录 `y_mean / y_change / y_sat` 等稳定性统计

## 9.3 Follow Expert（任务导向）

- 输入：GT affordance（Teacher）或 Estimated affordance（Student）+ robot_state + target_state  
- 训练：PPO  
- 目标：保持目标跟随（progress / heading / success），避障项弱但碰撞仍惩罚

## 9.4 Avoid Expert（任务导向 + 强安全约束）

**定义**：在确保安全边界的前提下尽可能朝任务方向推进。  
建议奖励结构：

- `r_prog = k1 * (dir_task · v_body_xy)`（仍向任务方向推进）  
- `r_safe = -k2 * exp(-(d_min - d0)/tau)`（连续风险成本）  
- `r_collision`：大惩罚 + 终止  
- `r_stability / r_smooth`：姿态与平滑约束  

> 避免“安全但停滞”的局部反射策略，确保 gate 有意义的两端点可选。

## 9.5 Gate 训练（冻结专家）

- 训练顺序：**Avoid → Follow → Gate**  
- Gate 输入需包含风险与紧迫度（例如 difficulty、clearance、target distance）  
- 加入 `|y_t - y_{t-1}|` 平滑惩罚；训练早期可启用安全 clamp 以避免 early collapse

## 9.6 Command Post-Processor（V5 强制）

MoE 融合后的命令必须通过 Post-Processor 再下发：

1) **限幅**：`vx, vy, ω` clamp 到底层可跟踪范围  
2) **Slew/滤波**：限制高频切换  
3) **风险钳制**：当 `d_min < d_safe` 时降低速度/转向  

> 该模块必须用于训练与测试，确保行为一致。

## 9.7 Teacher–Student（Affordance 蒸馏）

- Teacher 使用 GT affordance，Student 使用 Estimated affordance  
- Follow/Avoid 均可在 Teacher 上限策略后进行蒸馏  
- 蒸馏目标为 **cmd_vel**（可用 MSE / KL）

- 设置：狭长走廊，宽度略大于机器人通行宽度；目标在走廊内变速行走  
- 障碍：走廊内随机放置路障锥/箱体形成局部窄口  
- 体现点：保持距离 + 微绕行/减速排队，避免贴障碰撞  
- 泛化：走廊宽度、路障间距、摩擦系数、目标速度谱随机化

**S2 森林稀疏障碍（Random Poles / Forest）**  

- 设置：大平面随机立柱（圆柱/多边形），目标走向随机但有任务方向  
- 障碍：密度稀疏至中等，存在多条可行路径  
- 体现点：开放域避障 + 跟随速度约束（不能绕远）  
- 泛化：柱子半径/形状/密度/分布（Poisson/clustered）变化

**S3 门洞与房间序列（Doorway & Rooms）**  

- 设置：房间—门洞—房间串联，门洞宽度随机（含接近极限的紧门洞）  
- 障碍：门口附近随机堆放小障碍，形成门洞 + 拐角组合  
- 体现点：目标短暂遮挡/消失时仍需安全通过，避免卡门  
- 泛化：门洞宽度分布在测试外推

**S4 移动障碍交互（Crossing Pedestrians）**  

- 设置：目标沿主方向运动；2–6 个移动障碍横穿  
- 体现点：时序决策（减速让行 vs 绕行超越）  
- 泛化：速度分布、出现时机、横穿角度随机化

**S5 障碍密度跃迁（Sparse→Dense Transition）**  

- 设置：路径前半段稀疏后半段密集（或相反），目标速度随区域变化  
- 体现点：情境切换能力（稀疏区更积极，密集区更保守）  
- 泛化：密度分界位置、密度差、目标行为模式变化

**S6 结构化 OOD 组合（Non-convex / Clustered / Maze）**  

- 设置：训练中未出现的结构组合（非凸障碍/U 形、L 形、簇状柱群、迷宫式走廊等）  
- 体现点：跨结构泛化能力与策略余量  
- 泛化：形状组合、密度簇、通道拓扑在测试外推（严格 hold-out）
- 默认：cluster / nonconvex / maze 均匀混合采样；支持在配置中固定模板用于消融

**训练/验证/测试划分**  

- Train：S1/S2/S3/S4/S5（训练分布）  
- Val：S1/S2/S4（不同子区间/模板）  
- Hold-out Test：S6 结构化 OOD（非凸障碍 / 簇状分布 / 迷宫式走廊，训练中不出现）

**压力测试**  

- T1 目标短时消失：训练中低概率弱版；强版仅最终测试  
- T2 分布外组合：仅最终测试

# 结语：V5 的“不可妥协原则”（用来防止方案被实现稀释）

1) 底层不看深度相机：只用 proprio + 特权高度图（height map）  
2) 高层不控关节：只输出 cmd_vel 与门控 y  
3) y 仅作仲裁，不允许作为速度缩放或转向增益  
4) Command Post-Processor 必须用于训练与测试  
5) 必须有 camera_stability reward：视觉可用性是系统核心指标，不是口号  
6) 结构化 OOD hold-out 与 T1/T2 必须执行：否则泛化结论不可信
