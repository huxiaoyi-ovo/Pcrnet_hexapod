## 第一章 预测性冲突消解网络（PCR-Net）

### 1.1 核心思想

传统 MoE（Mixture-of-Experts）采用"看到障碍再切换"的反应式策略，存在滞后性和切换震荡问题。PCR-Net（Predictive Conflict Resolution Network）提出"预测未来冲突，提前平滑消解"的新范式：

- **时间维度扩展**：不仅基于当前状态，更预测未来 1 秒内的冲突概率
- **多维度调节**：不仅选择专家，更学习如何调和专家之间的矛盾
- **地形自适应**：根据地形难度动态调整行为保守程度

核心公式：

```
cmd = Follow(cmd) ⊕ Avoid(cmd) ⊕ Δ(confidence, terrain)
```

其中 ⊕ 表示非线性融合，Δ 为基于预测冲突的修正量。

### 1.2 架构设计

#### 1.2.1 整体架构

```
输入层：
├── 当前观测（proprioception + affordance）
├── 目标状态（相对目标位置）
└── 历史序列（过去 10 步状态，用于预测）

PCR Network：
├── Conflict Predictor（冲突预测器）
│   └── 输出：未来 10 步的冲突概率 P_conflict(t+1..t+10)
│
├── Resolution Policy（消解策略网络）
│   ├── 输入：当前 obs + 预测冲突 + Follow输出 + Avoid输出
│   └── 输出：调和参数 Δ[Δ_velocity, Δ_direction, confidence, style]
│
└── Blending Function（非线性融合层）
    ├── 动态混合权重：w = f(conflict_pred)
    ├── 基础命令：cmd_base = (1-w)·cmd_follow + w·cmd_avoid
    └── 最终命令：cmd_final = cmd_base + Δ

输出层：
├── cmd_vel（线速度指令）
├── confidence（置信度，用于知道何时停止）
└── style_factor（风格因子，用于可视化）
```

#### 1.2.2 冲突预测器（Conflict Predictor）

**网络结构**：轻量级 LSTM

```python
class ConflictPredictor(nn.Module):
    def __init__(self, obs_dim=67, hidden_dim=64, pred_horizon=10):
        self.lstm = nn.LSTM(
            input_size=obs_dim,
            hidden_size=hidden_dim,
            num_layers=2,
            batch_first=True
        )
        self.conflict_head = nn.Sequential(
            nn.Linear(hidden_dim, 32),
            nn.ReLU(),
            nn.Linear(32, pred_horizon),
            nn.Sigmoid()  # 输出概率
        )

    def forward(self, obs_seq):
        # obs_seq: [batch, time=10, obs_dim]
        hidden, _ = self.lstm(obs_seq)
        conflict_probs = self.conflict_head(hidden[:, -1, :])  # 取最后时刻
        return conflict_probs  # [batch, 10]
```

**训练目标**：

- 正样本：人工标注或规则生成（距离障碍 <0.5m 且朝向障碍时冲突=1）
- 损失函数：BCE Loss
- 目标准确率：>85%

**创新点**：

- 提前 0.5-1 秒预测冲突（10 步 × 0.05s 控制周期）
- 多步预测而非单步，捕捉冲突发展趋势

#### 1.2.3 消解策略网络（Resolution Policy）

**核心功能**：学习如何调和 Follow 与 Avoid 的矛盾

```python
class ResolutionPolicy(nn.Module):
    def __init__(self, obs_dim=67, pred_horizon=10):
        self.fusion_net = nn.Sequential(
            nn.Linear(obs_dim + pred_horizon + 2 + 2, 128),
            nn.ReLU(),
            nn.Linear(128, 64),
            nn.ReLU()
        )

        # 输出头
        self.delta_vel = nn.Linear(64, 2)      # [Δ_vx, Δ_vy]
        self.confidence_head = nn.Linear(64, 1)  # 置信度
        self.style_head = nn.Linear(64, 1)       # 风格因子

    def forward(self, obs, conflict_pred, cmd_follow, cmd_avoid, terrain_difficulty):
        # 拼接输入
        combined = torch.cat([
            obs,           # [batch, obs_dim]
            conflict_pred, # [batch, 10]
            cmd_follow,    # [batch, 2]
            cmd_avoid      # [batch, 2]
        ], dim=-1)

        features = self.fusion_net(combined)

        # 计算动态混合权重（基于整体冲突程度）
        w = conflict_pred.mean(dim=-1, keepdim=True)  # [batch, 1]

        # 基础命令混合
        cmd_base = (1 - w) * cmd_follow + w * cmd_avoid

        # 计算修正量
        delta_vel = torch.tanh(self.delta_vel(features)) * 0.3  # 限制修正幅度
        confidence = torch.sigmoid(self.confidence_head(features))
        style = torch.tanh(self.style_head(features))

        # 地形自适应缩放
        terrain_scale = 1.0 - 0.5 * terrain_difficulty  # 困难地形更保守
        delta_vel = delta_vel * terrain_scale.unsqueeze(-1)

        # 最终命令
        cmd_final = cmd_base + delta_vel

        return cmd_final, confidence, style
```

**关键创新 - 修正量 Δ**：

- **Δ_velocity**：速度调节（提前减速或加速）
- **Δ_direction**：方向微调（提前转向准备）
- **confidence**：系统置信度（低置信度时触发保守模式）
- **style**：风格因子（激进 vs 保守的可视化指标）

#### 1.2.4 非线性融合函数

传统 MoE 使用线性插值：cmd = (1-y)·cmd_follow + y·cmd_avoid

PCR-Net 使用非线性融合：

```python
def nonlinear_blend(cmd_follow, cmd_avoid, conflict_pred, delta):
    # 基于冲突强度的自适应权重
    w_base = conflict_pred.mean()

    # 非线性映射：低冲突时更信 Follow，高冲突时更信 Avoid
    w = torch.where(
        w_base < 0.3,
        w_base * 0.5,  # 低冲突：减小 Avoid 影响
        torch.where(
            w_base > 0.7,
            0.5 + w_base * 0.5,  # 高冲突：增大 Avoid 影响
            w_base  # 中等冲突：线性
        )
    )

    # 基础混合
    cmd_base = (1 - w) * cmd_follow + w * cmd_avoid

    # 应用学习到的修正
    cmd_final = cmd_base + delta

    # 后处理：限制加速度和曲率（物理可行性）
    cmd_final = limit_acceleration(cmd_final, max_acc=2.0)
    cmd_final = limit_curvature(cmd_final, max_curv=1.0)

    return cmd_final
```

### 1.4 与 MoE 的本质区别

| 维度       | 传统 MoE       | PCR-Net                       |
| -------- | ------------ | ----------------------------- |
| **时间维度** | 当前状态决策       | 预测未来 1 秒                      |
| **决策空间** | 选择 A 或 B（离散） | A ⊕ B + Δ（连续）                 |
| **调节维度** | 单一权重 y       | 多维度 [w, Δ, confidence, style] |
| **地形适应** | 无显式适应        | 基于 difficulty 动态缩放            |
| **可解释性** | y 是黑盒        | confidence + style 有物理意义      |
| **平滑性**  | 可能震荡         | 预测性调节天然平滑                     |

## 第二章 预测式风险预算仲裁（PCR-Net++）

> 本章定位：**替代第一章“学 Δ 残差”为主线方案**；保留 Follow/Avoid 两专家与 MoE 门控参数 y 的兼容性。
> 
> 核心目标：在“跟随目标 + 复杂避障 + 地形适应”的冲突场景中，比 y-only MoE 更有效、更丝滑，同时尽量避免新漏洞。

### 2.1 问题定义：冲突不是一维插值

Follow 与 Avoid 的冲突，本质是一个带约束的命令选择问题：

- Follow 想最大化进度/效率（更快接近目标）
- Avoid 想最小化碰撞风险/近碰风险（保留安全间隙）
- 复杂环境（窄门洞/密集柱群/开放域绕行）会让“可行命令集合”随位置和方向快速变化

因此，仅用一个 y 做线性混合：

```
cmd = (1-y) * cmd_follow + y * cmd_avoid
```

容易出现两类问题：

- **滞后**：看到危险才切换，已经来不及提前减速/摆位
- **震荡**：危险边界附近 y 抖动，命令突变（急刹/急转），导致失败或不稳定

### 2.2 核心思想：用 (w, β) 分解“提前性”和“保守度”，并联动后处理

PCR-Net++ 不再直接学习自由残差 Δ(cmd)。改为学习两个可解释调节量：

- `w ∈ [0,1]`：**预测式冲突 prior**（提前 0.5-1s 调整“更信 avoid 还是 follow”）
- `β ∈ [0,1]`：**风险预算/保守度**（越大越保守），用于**联动 Command Post-Processor 的安全阈值与平滑约束**

同时保留 MoE 的 `y`（结构门控）作为一个“模式/结构性选择”变量：

- `y`：结构性模式选择（follow-like vs avoid-like）
- `w`：预测式 prior（提前性）
- `β`：风险预算（可控性 + 部署旋钮），并作用到后处理

最终命令链：

```
cmd_follow, cmd_avoid  --(y, w)-->  cmd_base  --(Post-Processor; β)--> cmd_final
```

### 2.3 系统结构与接口

#### 2.3.1 输入/输出

输入（建议最小集合，吞吐友好）：

- 当前观测：proprioception + goal（相对目标）
- 当前可通行信息：affordance/clearance/difficulty（Teacher 用 GT affordance；Student 后续再蒸馏）
- 专家候选命令：`cmd_follow`、`cmd_avoid`（建议使用 3D：vx, vy, omega）
- 短历史特征（不强制 LSTM）：最近 K 步的 `{clearance, Δcmd, progress, collision_flag}` 统计量

输出：

- `w`（预测式 prior）
- `β`（风险预算）
- （可选）`confidence`（低置信度时触发 β↑ 的保守模式；不建议直接“停”）

#### 2.3.2 推理时序与预测 horizon

高层控制周期为 `dt_high = 0.1s`（10Hz），推荐预测 horizon：

- `H = 10`（1.0s lookahead）或 `H = 5`（0.5s lookahead）

注意：PCR-Net++ 的“预测性”不必强依赖 LSTM；MVP 可用短历史统计特征 + MLP 先验证收益。

### 2.4 决策与融合：从 y-only 到 y+w+β

#### 2.4.1 y 与 w 的融合：y_eff

定义一个有效门控：

```
y_eff = clamp((1-λ) * y + λ * w, 0, 1)
```

- `y` 来自原 MoE 门控网络（或你已有 gate policy）
- `w` 来自 PCR-Net++ 的预测 prior
- `λ` 可取常数（例如 0.5），或随冲突强度自适应（冲突越强越信 w）

#### 2.4.2 基础命令：cmd_base

```
cmd_base = (1 - y_eff) * cmd_follow + y_eff * cmd_avoid
```

### 2.5 β 联动 Post-Processor：把“丝滑与安全”变成硬约束而非靠 Δ 学出来

Command Post-Processor 负责：

- 命令限幅：`max_cmd`
- 命令变化率限制：`max_delta`（slew rate）
- 风险缩放/安全距离：`safe_distance/free_distance`（由 clearance/affordance 估计）

PCR-Net++ 的关键是：**β 连续调节这些约束的强度**。

#### 2.5.1 参数映射（示例）

```
safe_dist(β) = lerp(safe_min, safe_max, β)
free_dist(β) = lerp(free_min, free_max, β)

max_cmd_lin(β) = lerp(v_fast, v_safe, β)
max_cmd_ang(β) = lerp(w_fast, w_safe, β)

max_delta_lin(β) = lerp(slew_fast_lin, slew_slow_lin, β)
max_delta_ang(β) = lerp(slew_fast_ang, slew_slow_ang, β)
```

直觉：

- β↑（更保守） => safe/free 距离更大，速度上限更低，变化率更小 => 更安全更平滑
- β↓（更激进） => 更快更灵活，但仍受硬约束保护

#### 2.5.2 最终命令

```
cmd_final = PostProcessor(
    cmd_base,
    safe_distance=safe_dist(β),
    free_distance=free_dist(β),
    max_cmd=(max_cmd_lin(β), max_cmd_lin(β), max_cmd_ang(β)),
    max_delta=(max_delta_lin(β), max_delta_lin(β), max_delta_ang(β)),
    # 其它风险缩放/钳制参数保持统一口径
)
```

> 关键优势：把“丝滑/安全”交给统一后处理保证，避免 Δ 残差成为新的 hack 点。

### 2.6 w 的训练信号：避免“离得近就冲突”的弱标签

w 的目标不是重复 clearance，而是学习**在给定候选命令下的未来可行性差异**。

推荐两种训练信号（可叠加）：

1) **弱监督（吞吐友好）**：基于 affordance 的“命令条件风险”打标签
- 用当前 affordance 距离图/clearance 估计，沿候选命令方向采样未来 τ 秒的路径段，得到：
  - `risk_follow = RiskAlong(cmd_follow)`
  - `risk_avoid  = RiskAlong(cmd_avoid)`
- 构造软标签：
  - `w* = sigmoid(k * (risk_follow - risk_avoid))`
2) **RL 主任务信号**：w 通过总体回报学习（progress + collision + risk + smooth）
- w 不是单独优化预测准确率，而是为了最终行为更好

这样可以避免 predictor 退化为“离障碍近 = 1”的无用预测。

### 2.7 训练流程（与现有 follow/avoid pipeline 兼容）

#### Stage 0：专家训练（Follow / Avoid）

- 在 S1/S2（curriculum）分别训练 `π_follow` 与 `π_avoid`
- 两者共享同一观测接口、同一 post-processor（保证部署一致）
- 区别只在 reward 权重：Follow 更重 progress/time；Avoid 更重 risk/collision

#### Stage 1：训练 PCR-Net++（冻结专家，主线推荐）

- 冻结 `π_follow/π_avoid`
- 训练输出 (w, β) 的仲裁网络（以及 y 若需要）
- 奖励建议：
  - progress_to_goal（主项）
  - collision_penalty（强）
  - risk_barrier（与 β 联动后的 clearance 一致）
  - time_penalty（保底非 0，防止“停住最安全”）
  - smoothness：`cmd_jitter`、`Δy_eff`、`Δβ`
- 可选辅助损失：`L_w = BCE(w, w*)`

#### Stage 2：端到端微调（可选）

- 若 Stage 1 上限不足：解冻部分专家或小学习率联合微调
- 强制监控：collision/time/jitter 是否出现 trade-off 崩塌（避免灾难性遗忘）

### 2.8 评测指标与消融（保证“比 y-only 更丝滑更有效”是硬结论）

#### 2.8.1 指标（在原 Success/Collision/Time 基础上补充）

- `cmd_jitter`：`Var(Δcmd)` 或 jerk 代理
- `switch_rate`：`Var(Δy_eff)`、`Var(Δβ)`、切换次数
- `near_miss`：clearance 低于阈值的时间占比/积分（比纯 collision 更敏感）
- Pareto 曲线：Completion Time vs Collision Rate vs cmd_jitter

#### 2.8.2 消融矩阵（最小集合）

- Baseline：y-only MoE
- y + w：只有预测 prior
- y + β：只有预算联动后处理
- y + w + β：完整 PCR-Net++
- β 不联动后处理 vs 联动后处理（关键消融）

### 2.9 风险与对策（隐藏漏洞清单）

- 风险 A：β 学会“保守=停住”
  
  - 对策：time_penalty 保底；progress 保底；对低速/零速加门控惩罚

- 风险 B：w 学到场景标签/捷径
  
  - 对策：β、w 采样/监督与场景类型/难度解耦；输入显式包含候选 cmd；用消融证明 w 非冗余

- 风险 C：吞吐不达标（LSTM 过重）
  
  - 对策：MVP 先用 MLP+短历史统计；LSTM 作为可选升级并报告推理耗时

- 风险 D：安全/平滑靠网络而非机制
  
  - 对策：坚持“β 联动后处理/可行域”为硬约束主线；Δ 残差只作为后续小幅增强（受限输出）

**备注（实现路线建议）**：先在 S1/S2 做 MVP：y+w+β + β 联动 post-processor（不引入 LSTM、不引入自由 Δ）。待指标曲线稳定后，再评估是否需要引入受限 Δ（例如仅输出小幅速度缩放/角速度偏置）作为后续增强。
